# 第 62 章 机器学习基础

机器学习可以用于实时通信中的人脸检测、背景替换和噪声抑制等任务，但它首先需要训练数据、模型和足够的计算资源。本章用入门视角说明监督学习与无监督学习、训练与推理的区别，并解释 WebAssembly 为什么能帮助浏览器运行这类计算密集型算法。

## 如何理解人工智能与机器学习

课程讲师在讨论中不把人工智能（AI）与机器学习（ML）作严格区分，因为多数日常讨论也不会区分二者。这是一种便于展开课程的表述，并不意味着两个概念在所有语境中都没有差别。

课程还引用了一种带有调侃意味的定义：“人工智能就是尚未被实现的任何事情。”一旦机器已经能够完成某项工作，人们往往就不再把它视为人工智能。无论是否采用这种定义，理解实时通信中的机器学习，都需要先看清它怎样从数据中学习。

## 监督学习与无监督学习

机器学习主要有两种学习方式。它们最根本的区别，在于训练开始时数据是否已经带有标签。

| 对比项 | 监督学习 | 无监督学习 |
| --- | --- | --- |
| 数据 | 预先标注，已知数据代表什么 | 没有标签，不预先指定数据属于哪一类 |
| 学习过程 | 根据过去的标注结果，预测新数据的输出 | 发现数据的内在结构、聚类或趋势 |
| 优势 | 有可能找到较优解；有标签作为依据，结果较容易解释 | 无须手工标注，可以直接处理原始数据，部分过程更容易自动化 |
| 困难 | 准备和标注数据需要大量人工工作 | 仍需要训练数据，训练过程比较复杂 |
| 常见用途 | 排名、推荐、分类、回归分析 | 聚类、异常检测 |

### 监督学习：从已知答案学习

监督学习可以让机器回答“是”或“否”一类问题。课程以早期应用“Hotdog or Not Hotdog”为例：机器分析一张图片，判断它与热狗的相似程度，进而识别图片是不是热狗。

训练时，开发者不仅向机器提供图片，还告诉它哪些图片是热狗、哪些不是。机器利用这些带标签的样本学习，之后再根据过去出现过的输入与输出，对新数据作出预测。标签也使训练结果更容易理解和评估。

代价在于，标签不是天然存在的。为大量样本逐一添加正确标签，需要投入显著的人工准备成本。

### 无监督学习：从未标注数据中发现结构

无监督学习不预先告诉机器每条数据的含义或类别。课程以 Twitter 趋势为例：系统查看人们正在讨论什么，再从讨论内容中归纳并展示最热门的趋势。这里的目标不是按照现成答案预测标签，而是分析原始数据并发现其中的结构。

无监督学习常用于聚类和异常检测。由于不需要人工预先标注，部分流程可以自动化；但这不等于不需要训练，也不意味着训练简单。如何从没有标签的数据中训练出有用结果，本身就是复杂问题。

## 从训练数据到推理结果

机器学习系统可以把工作过程分成训练和使用模型两个阶段。

### 训练阶段

1. 准备一批已经掌握的数据，作为训练数据。
2. 让训练算法在数据上运行。
3. 训练算法生成模型；模型可以理解为后续可供使用的一组数据点。
4. 根据需要继续优化模型，例如缩小模型，或随时间改进它。

训练通常离线进行，可以选择合适的时间和计算手段，不要求它跟随每一次实时会话同步完成。

### 推理阶段

真正使用模型时，运行的是**推理算法**。推理算法同时接收两类数据：

- 训练得到的模型数据；
- 当前新输入的数据。

算法据此产生所需结果，例如对输入分类、聚类，或完成其他目标任务。

在实时通信中，推理往往必须实时执行，因为应用希望立即或尽可能快地得到结果。训练与推理由此具有不同的运行要求：训练可以离线完成，推理则直接处于媒体处理的时效约束之下。

## 神经网络与简单模型

神经网络是课程所述时期机器学习中的基本方法之一。网络在训练过程中形成，随后通过不同组合的隐藏层，把输入转换为输出。课程列举了 CNN、GNN 等不同类型的神经网络。

不过，机器学习并不必然意味着复杂神经网络。线性回归也是机器学习：给定图上的一批点，寻找一种趋势，也就是找到一条能让大多数点尽可能靠近它的线。这个例子说明，核心问题是从数据中得到可用于分析的模型，而不是模型看起来是否复杂。

## 推理需要的资源

机器学习，特别是推理阶段，需要重视两类资源：

- **CPU**：运行推理算法、处理当前输入；
- **内存与模型存储**：保存模型，并为计算过程提供所需空间。

因此，把推理放到浏览器中并不是单纯移植一段代码。模型本身需要存放，算法也需要足够的计算能力才能及时给出结果。

## WebAssembly：在浏览器中运行重型算法

Coding Horror 网站提出的阿特伍德定律（Atwood’s Law）认为：“任何能够用 JavaScript 编写的应用，最终都会用 JavaScript 编写。”课程把机器学习也纳入这一趋势，但同时指出它的现实障碍：机器学习需要大量 CPU，JavaScript 在许多计算密集型场景中可能不够快。

传统网页中，HTML 被解析并显示，JavaScript 经编译后在浏览器中运行。WebAssembly 为浏览器增加了另一条执行路径，其代码可以在浏览器中即时转换为机器码，从而提高实际执行性能。

课程描述的生成过程是：

1. 从现有编程语言和代码开始。课程列举了 C、C++、Python、Go、Elixir 等语言。
2. 对代码进行交叉编译，将其转换为 WebAssembly。
3. 得到 WASM 文件。
4. 让浏览器加载并运行该文件，在执行时把 WebAssembly 转换为机器代码。

这使机器学习及其他复杂算法有机会直接在浏览器内运行，而不必完全依赖 JavaScript 的执行性能。

## 在实时通信中的应用

课程列举了 WebAssembly 与机器学习结合的多类用途：

- **视频处理**：人脸检测、手势识别、背景替换、光照修正等；
- **语音处理**：主要用于噪声抑制和噪声消除；
- **丢包相关处理**：也有少量涉及。

WebAssembly 在实时通信中的作用并不限于机器学习。它还可用于媒体网络栈和既有代码移植；在这些场景中，重点是把它当作跨平台编译目标，而不是训练或运行模型。

## 小结

监督学习依赖带标签数据来预测输出，无监督学习则从未标注数据中寻找结构。训练算法把训练数据转化为模型，推理算法再结合模型和新输入产生结果；在实时通信里，推理需要尽量即时完成。模型存储、内存和 CPU 因而成为浏览器端部署的重要约束。WebAssembly 提供了更高效的浏览器执行路径，可支持视频、语音等计算密集型处理，也可用于与机器学习无关的媒体栈移植。
