# 第 33 章 模块四小结

本模块介绍了 WebRTC 中音频、视频编解码器的工作方式，以及哪些编解码器与 WebRTC 相关。理解以下内容，比记住一串编解码器名称更重要。

## 有损压缩与感知取舍

这里讨论的主要是**有损编解码器**：先舍弃人耳或人眼不易察觉、对实际感知不重要的信息，再压缩剩余数据。编码并非无损地保存一切，而是在质量、数据量与感知效果之间取舍。

## 资源消耗与场景选择

编解码器很复杂，往往消耗大量 CPU 和内存，是明显的资源密集型组件。因此，没有脱离使用场景的最佳选择；应针对终端能力、媒体类型和业务目标，选用最合适的方案。

## 编码器包含启发式与艺术性

编码结果依赖启发式方法。编码器并不只是机械执行一个唯一、固定的算法，其设计和调优带有很强的创作与艺术成分。评估编解码器时，需要关注具体实现和实际输出，而不能只看标准名称。

## 从编码走向媒体处理

编解码器解决的是媒体如何表示和压缩。接下来还需要处理编码后的数据，使其能够真正通过网络传输，这就进入了媒体处理的范围。
