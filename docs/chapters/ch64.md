# 第 64 章 WebRTC 服务器端基础：部署内容

部署 WebRTC 产品，不能只在浏览器中启用 WebRTC。浏览器或其他客户端设备确实是实时通信的起点，但一个可以使用的应用还需要后端配合：交付应用、运行应用逻辑、帮助双方找到彼此、协助穿越防火墙和 NAT，并在需要时处理媒体。本章梳理这些组件各自负责什么，以及最小部署与完整服务之间的差别。

## 客户端：实时通信的起点

最常见的 WebRTC 载体是网页浏览器，但客户端不限于浏览器。开发者也可以把 WebRTC 嵌入移动应用或 PC 应用，构建能够通信的产品。

无论采用哪种载体，客户端都只是部署的一部分。“设备支持 WebRTC”并不意味着设备已经知道应用在哪里、要与谁通信，也不意味着它一定能够穿过双方之间的网络设备直接建立媒体连接。

## Web 服务器与应用后端

用户访问网站 URL，或点击打开应用后，客户端需要与后端交换数据。Web 服务器及相应应用后端承接这部分工作，与浏览器、Web 应用或其他客户端通信，并承载应用自身的流程和逻辑。

这一层可以使用构建网站和互联网应用的既有技术。它的必要性来自产品本身：实时通信通常只是应用的一项能力，应用仍需要页面、业务流程和后端支持。WebRTC 并没有取代这些常规组件。

## 信令服务器：让双方先找到彼此

WebRTC 可以建立点对点通信，但在开始点对点连接之前，一端必须先知道另一端在哪里。信令服务器负责这一阶段的协调。

它可以：

- 把两个不同的浏览器联系起来，使它们能够开始通信；
- 把浏览器与联络中心的客服人员连接起来；
- 在应用逻辑控制下传递建立会话所需的消息。

因此，“点对点”描述的是后续媒体连接可以具有的路径，并不表示整个系统不需要服务器。没有信令协调，浏览器通常连通信对端都无法确定。

Web 服务器和信令服务器是逻辑上不同的职责，但不一定要占两台独立机器。课程指出，实际部署中经常把二者合并到同一服务器中。

## STUN/TURN 服务器：协助建立可用连接

信令服务器让双方找到彼此之后，还要解决它们怎样真正通信的问题，尤其是路径上存在防火墙或 NAT 设备时。课程有时把这一组服务称为 **ICE 服务器**，更准确地说是配合交互式连接建立（ICE）过程的 **STUN/TURN 服务器**。

其工作结果有两种：

1. **能够直接通信**：双方通过 ICE 协商找到可用路径，媒体可以直接传输，协商过程使用 STUN/TURN 服务。
2. **无法直接通信**：双方需要由 TURN 服务器中继媒体，才能继续维持会话。

所以，STUN/TURN 服务并不意味着所有媒体都必须经过服务器；它的目标是协助穿越网络障碍，在无法直连时再提供中继路径。没有这一部分，部署可能无法穿越防火墙和 NAT 设备。

## 媒体服务器：按需增加的后端媒体处理

最小系统之外，还可以部署一个或多个媒体服务器。它不是每个 Hello World 示例都必须具备的组件，但在后端需要处理媒体时非常重要。

课程列出的用途包括：

- **录制与回放**：保存希望保留的会话媒体，并在需要时播放；
- **与其他服务协作**：例如把会话接入面向海量受众的直播服务；
- **多方通话**：把多个参与者放入同一个房间、同一场通话中。

是否需要媒体服务器、需要多少媒体服务器，取决于产品是否要承担这些额外复杂性，不能仅凭“使用 WebRTC”作出统一判断。

## 最小部署与按需扩展

课程给出的最基础 WebRTC 示例，可以由以下部分组成：

| 组件 | 基本职责 | 在最小示例中的地位 |
| --- | --- | --- |
| 浏览器、移动应用或其他支持 WebRTC 的设备 | 发起和参与实时通信 | 必需 |
| Web/应用服务器 | 与客户端交换应用数据，承载应用流程和逻辑 | 必需 |
| 信令服务器 | 帮助对端发现彼此并协调会话建立 | 必需 |
| STUN/TURN 服务 | 配合 ICE 协商，协助穿越防火墙和 NAT，必要时由 TURN 中继媒体 | 必需 |
| 媒体服务器 | 录制、回放、直播协作、多方媒体处理 | 可选，按场景增加 |

其中，Web 服务与信令能力可以合并部署。客户端、Web/信令后端和 STUN/TURN 服务，足以构成课程所说的最小可行 Hello World 或 WebRTC 示例；媒体服务器则在产品需要后端媒体能力时加入。

## 小结

WebRTC 产品部署由客户端和多种后端职责共同组成。Web/应用服务器支撑应用本身，信令服务器帮助双方发现并协调连接，STUN/TURN 服务协助建立可穿越网络障碍的媒体路径，媒体服务器则按需提供录制、直播协作和多方通话等能力。设计部署时，应先分清这些逻辑职责，再决定哪些可以合并、哪些必须独立，以及哪些只在更复杂的场景中出现。
