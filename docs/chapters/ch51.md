# 第 51 章 常见 WebRTC 设计模式

课程进入最后的模块七。此前介绍的概念已经构成开发 WebRTC 产品和理解其架构的基础；本模块将把这些概念用于具体场景，而不是继续孤立地讨论各项技术。

## 先理清媒体与信令路径

本模块首先关注 WebRTC 中的媒体流。实际设计中，媒体与信令分别经过哪里，很容易造成混淆。因此，需要明确 STUN、TURN 和媒体中继的作用，加入媒体服务器后路径会发生什么变化，以及信令最终流经哪些组件。看清这些路径，才能准确描述架构需要实现的目标。

## 从四类典型场景推导架构

随后，课程将运用此前介绍的不同组件，从零开始分析四类用例：

1. **会议录制**：会议如何录制，有哪些可选操作、决策点和注意事项。
2. **多方会议**：屏幕布局如何影响实际所需的架构。
3. **网络研讨会与低延迟直播**：这些场景意味着什么，以及级联等机制如何融入架构。
4. **PSTN 连接**：如何理解公共交换电话网络连接，以及可以从哪些不同角度设计它。

这些场景的重点不是套用同一张架构图，而是从各自需求出发，组合课程中已经介绍的技术与组件。
