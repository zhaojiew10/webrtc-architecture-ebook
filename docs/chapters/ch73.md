# 第 73 章 watchRTC 简介

watchRTC 是 testRTC 的真实用户被动监控产品。它从用户设备收集 WebRTC 遥测数据，帮助团队理解线上用户的实际体验，并从服务全局逐层深入到具体会话、用户、媒体通道和 API 调用，用于发现异常、隔离问题及事后分析。

## 定位：直接观察真实用户体验

媒体服务器统计只能反映服务器一侧看到的情况，watchRTC 则通过客户端集成，直接从用户设备收集数据。团队无需主动模拟一次通话，即可观察真实用户正在经历的会话。

这种监控方式支持两种互补视角：

- **全局视角：** 查看部署中所有用户的网络表现，迅速识别特定用户、位置或服务的离群值和异常行为；
- **细节视角：** 按需逐层深入，获取完整的事后分析信息，以定位或修复问题。

因此，watchRTC 的重点不是主动发起测试，而是从正在运行的服务中积累真实用户数据。

## 三步使用流程

课程将 watchRTC 的使用概括为三个步骤：

1. **集成 SDK。** 将 watchRTC SDK 集成到客户端应用中。
2. **收集真实用户遥测。** 完成初始集成后，即可从线上活跃用户收集数据。
3. **分析结果。** 数据积累到足够规模后即可开始分析；课程称这一过程几乎不需要长时间等待。

后续分析都在 testRTC 控制面板中进行，从汇总视图逐步进入具体对象。

## 全局概览与筛选

watchRTC 的 Highlights 视图展示一段时间内收集到的会话。默认示例呈现全天数据，使用者可以：

- 调整时间范围，查看不同时段；
- 按标签过滤；这些标签可为会话中的特定用户设置；
- 查看会话平均持续时间、平均参与者数量、连接数量、收集的分钟数，以及其他平均指标和评分。

全局视图还提供全天会议与分钟数的分布、不同会议规模的统计，以及连接到服务的会话并发情况。其中，会议规模的分组区间可以配置。

这一层适合先判断服务整体表现，再决定应检查哪个时段、哪类用户或哪种规模的会议。

## 从会话深入到用户

在汇总结果之后，可依据标签、时间和用户数量等条件选择会话或用户继续分析。会话视图沿用 testRTC 其他产品的展示方式，可查看评分、比特率、丢包率和抖动。

课程示例中的会话有两位参与者，因此既可以按对端分别查看，也可以查看整个测试的平均值。随后还能继续进入其中任意一位用户。

单用户视图提供该用户使用的机器和设备信息，以及本次会话中的不同媒体通道。演示会话包含：

- 两路出站 VP8；
- 一路入站 VP8；
- 一路 Opus 音频通道。

点击具体通道后，可继续查看相应细节。图表演示包括视频比特率与丢包率的对照，也可以改为显示帧率、抖动，或切换到音频信息。

## 深入连接配置与 API 调用

如果媒体和网络图表仍不足以解释问题，还可以进一步查看：

- 对等连接配置；
- API 调用；
- 完整 SDP；
- 额外收集的指标及其图表。

由此，分析路径从“哪个服务或用户表现异常”，一直延伸到“该用户的媒体通道出现了什么变化”以及“对等连接如何配置、API 如何调用、SDP 内容是什么”。课程只展示这些分析入口和信息类型，没有在此展开具体故障的诊断结论。

## 适用场景

watchRTC 适合已经有真实用户流量、希望持续理解线上体验的 WebRTC 服务。它尤其适用于：

- 从全体用户中筛查异常用户、异常地点或异常服务；
- 对比不同时间段、标签和会议规模的表现；
- 从全局指标下钻到单个会话、参与者及媒体通道；
- 利用完整 SDP、连接配置和 API 调用记录进行事后分析。

与主动测试不同，它回答的是“真实用户现在实际经历了什么”；与只看服务器统计不同，它强调来自用户设备的直接观测。

## 小结

watchRTC 通过客户端 SDK 被动收集真实用户遥测，以全局汇总、标签和时间筛选发现异常，再逐层深入会话、用户、媒体通道、对等连接配置和完整 SDP。它把服务整体视角与细粒度事后分析连接起来，适用于线上 WebRTC 用户体验监控和问题隔离。
