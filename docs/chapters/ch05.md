# 第 5 章 学习资源

WebRTC 的学习资料分布在课程、技术博客、邮件列表、会议录像和社区协作项目中。本章按用途整理课程点名的资源，帮助读者在架构设计、协议分析、动手实践、故障排查和版本跟踪之间选择合适的入口。

## 课程体系

免费的 WebRTC Basics 是 Advanced WebRTC Architecture 的第一模块。后者从多个角度解释 WebRTC 怎样工作、怎样使用，以及如何围绕它设计和实现解决方案。除此之外，课程讲师还提供以下学习路径：

| 资源 | 适合的学习目标 |
| --- | --- |
| **Low Level WebRTC Protocols** 与 **Higher Level WebRTC Protocols** | 深入构成 WebRTC 的协议和内部机制，包括 RTP、RTCP、SRTP、SDP、抖动缓冲等。适合已经不满足于 API 使用、希望继续研究底层细节的开发者。 |
| **WebRTC: The Missing Codelab** | 由讲师与 Philipp Hancke 共同制作，围绕一段实现简单 WebRTC 通话的代码，讲解怎样运行和使用，以及编写时的思考过程，并配有练习。两门协议课程和这门 Codelab 均由两人合作完成。 |
| **WebRTC Tooling** | 介绍市场上的商业工具、开源项目，并访谈工具背后的开发者，适合了解生态和方案选择。 |
| **Supporting WebRTC** | 面向在客户现场支持 WebRTC 实施的一级、二级和三级支持人员，重点不是产品设计，而是从调试视角理解 WebRTC、定位问题。 |

前四类资源主要面向开发者；Supporting WebRTC 则把同样的技术放到支持和服务流程中考察。

## 技术网站、邮件列表与通讯

| 资源 | 内容与特点 |
| --- | --- |
| **WebRTC Hacks** | 由 Chad Hart 维护，也接受客座文章。内容技术性强，通常聚焦 WebRTC 的具体问题。课程特别指出，即使是发布时间很早的文章，也有许多仍然值得阅读。 |
| **WebRTC for Developers** | 由一位长期从事 WebRTC 的法国开发者 Olivier 维护，文章涉及 WebRTC API、相关实验和整个生态。其特点是通过实际探索、检查和验证解释技术如何工作。 |
| **WebRTC Weekly** | 每周通过邮件发布的通讯，汇集 WebRTC 行业中公开的信息、公告和文章，适合持续跟踪生态动态。 |
| **Discuss WebRTC** | WebRTC 社区的邮件列表或讨论组，由 Google 和 libwebrtc 团队维护。除问题讨论外，尤其值得关注发布说明和公告（PSA）。 |
| **WebRTC Glossary** | BlogGeek.Me 内的术语小站，覆盖与 WebRTC 直接或间接相关的术语，适合快速查词；部分词条还配有视频。 |
| **BlogGeek.Me** | 课程讲师的主要网站，提供 WebRTC 相关长文。按课程录制时的情况，大约每两到三周更新一次，也可从这里了解讲师的其他服务和产品。 |

这些资源的更新节奏和用途不同：Glossary 适合解决术语问题，WebRTC Hacks 和 WebRTC for Developers 适合深入具体主题，Weekly 与 Discuss WebRTC 则更适合持续跟踪。

## 会议与社区协作读物

**Kranky Geek** 是自 2014 年开始举办的年度活动，疫情期间曾转为远程或线上形式。活动邀请个人和公司分享使用 WebRTC 的经历、使用方式及其原因，内容可在 YouTube 上找到。课程认为其中不少录像经受住了时间考验，仍有参考价值。

课程还简要提到 **CommCon**、**IIT RTC**，以及 Facebook/Meta 的 **RTC at Scale** 活动，可作为了解实时通信实践和规模化经验的补充入口。

偏好系统化阅读的读者可以关注 **WebRTC for the Curious**。这是由 Pion 项目背后的 Sean 创建的社区驱动网站，从不同角度解释 WebRTC，同时也是一本协作维护的书，读者可以通过 GitHub 参与更新和编辑。

## 纸质书、电子书与持续跟踪

对于纸质书，课程在录制时没有给出具体推荐。原因是过去推荐的一些书已经显得陈旧：有的仍使用旧版 WebRTC API，有的解释已不适合当时的技术环境。讲师自己的电子书则可通过 WebRTCcourse.com 获取。

如果需要更紧密地跟踪浏览器与 WebRTC 版本变化，课程还介绍了 **WebRTC Insights**。这项服务由讲师与 Philipp Hancke 共同运营，每两周发送一次邮件，汇总这段时间发现的技术问题和市场观察，尤其关注：

- WebRTC 新版本带来的问题；
- 浏览器测试版或正式发布中出现的已知问题；
- 对直接使用 WebRTC 构建自有解决方案的团队有影响的变化。

它是一项收费服务，课程依据其客户反馈认为具有价值。与基础教程相比，这类双周通讯更偏向版本风险识别和持续技术跟踪。

## 使用资源时注意时效

课程提供的网站和资源都有配套链接，便于直接访问。视频录制于某个固定时间点，而链接清单可以先于视频更新；后续出现有价值的新资源时，也可能被加入清单。因此，使用本章资源时，应把课程当前提供的链接和资料说明一并纳入参考，而不能只依据录制当时的内容。

选择资源的原则也很简单：先明确自己是在学习架构、阅读协议、编写代码、排查故障，还是跟踪版本，再选择对应的课程或信息源，不必用同一种资料解决所有问题。
