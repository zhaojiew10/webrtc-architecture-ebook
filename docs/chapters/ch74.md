# 第 74 章 qualityRTC 简介

qualityRTC 是 TestRTC 面向 WebRTC 应用提供的产品之一，用于排查最终用户的网络与连接问题。TestRTC 的产品方向涵盖 WebRTC 应用的测试、监控和支持，而 qualityRTC 重点解决的是：当用户已经遇到问题时，如何快速收集有用的信息并定位根因。

## 从用户投诉到根因定位

用户报告的问题往往只有现象，例如无法加入会话、声音发闷或断续、音视频延迟，以及整体媒体质量差。支持人员如果只靠这些描述逐项询问，定位过程通常很慢。

qualityRTC 的目标是提高用户满意度，并缩短理解和解决网络问题所需的时间。它不会代替服务提供方修复所有问题，而是尽可能快地帮助支持团队找到问题的根本原因。

其使用方式包括以下几个要点：

- **终端用户无需安装软件。** 用户通过简单的网页界面完成测试，降低求助过程中的操作门槛。
- **按支持需求收集信息。** 测试结果汇集后，可供支持团队审核并继续协助客户。
- **与被测 WebRTC 基础设施整合。** 整合工作由 TestRTC 一侧完成，使测试直接面向实际服务，而不是只检查一个与业务无关的通用网络目标。
- **支持白标与定制。** 页面可以使用服务提供方自己的品牌、样式和交互流程。

## 一次端到端测试包含什么

课程演示从一个语音测试页面开始。不同语音或视频应用可以展示不同的测试组件，具体组件取决于要解决的问题。用户填写信息并启动测试后，qualityRTC 会检查当前用户网络到目标服务之间的连接状况。

启动页和测试流程均可定制，包括：

- 要收集哪些用户数据，以及使用哪些输入字段；
- 实际运行哪些测试；
- 测试所用的密码或 URL 等配置。

结果页用绿色表示正常、红色表示异常。演示中检查了网络吞吐量、通话质量、TURN 连通性、用户位置和带宽速度等项目。多数结果正常，但 DNS 查找存在问题；展开详细结果后，可以看到其中一个域名无法连接，原因是该域名不存在。

这说明测试不应只是给出一个笼统的“网络不好”。每项测试都应围绕特定问题设计，并给出足以继续分析的细项结果。qualityRTC 的知识库还提供了多种现成测试和组件，此外也可以配置其他测试选项。

## 用户结果与支持后台的分工

终端用户看到的是易于理解的结果，支持团队则可以在后台仪表板中查看历次测试。后台同样用颜色区分状态：红色表示存在问题，绿色表示正常。

支持人员打开刚完成的测试后，可以进一步查看日志。日志能够补充结果页没有展开的环境信息，例如：

- 浏览器类型；
- 操作系统；
- 测试使用的耳机；
- 测试使用的麦克风。

因此，面向用户的简洁结果与面向支持人员的详细诊断并不冲突：前者帮助用户完成自助检查，后者为人工支持保留定位所需的证据。

## 接入方式

qualityRTC 可以作为用户的自助服务工具。服务提供方既可以从自己的网站链接到测试页，也可以把测试嵌入网站，并按照自身品牌风格、页面流程和 WebRTC 基础设施进行定制。

它的核心价值不是替代所有支持工作，而是把“用户描述故障”转化为一套可复现、可查看、与真实服务相关的测试数据，从而缩短支持团队找到网络与连接问题根因的路径。
