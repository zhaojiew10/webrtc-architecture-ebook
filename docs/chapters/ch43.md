# 第 43 章 第三方框架与服务

前面的模块已经讨论信令传输、网络、编解码器和媒体处理。模块六将视角转向生态系统，关注开发者实际如何使用 WebRTC 构建产品，以及哪些第三方能力可以减少重复工作。

## 本模块的学习路线

本模块将依次讨论：

- **开发策略**：从自行构建开始，比较开源方案、商业方案和通信平台即服务（CPaaS）。
- **信令替代方案**：了解可用于 WebRTC 信令的不同框架与服务。
- **媒体服务器替代方案**：比较不同的媒体服务器选择。
- **完整托管方案**：介绍 WebRTC PaaS，也就是以 WebRTC 为重要通信基础设施的 CPaaS。
- **语音框架**：连接遗留系统、公共交换电话网络（PSTN）或现有 SIP 基础设施时可采用的框架。
- **测试与监控**：说明这一经常被忽视的环节，以及它对实际服务的重要性。

这一模块的重点不是孤立罗列工具，而是理解不同工具在整体架构中的位置，以及它们如何改变开发、运营和维护工作。
