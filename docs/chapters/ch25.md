# 第 25 章 极客数字媒体入门

数字音频、数字视频、流媒体和压缩常被包装成只有少数专家才能理解的领域。它们当然包含深厚的数学与工程问题，但这种神秘感并不合理。以课程录制时的硬件发展为背景，工作站较早就能从容处理数字音频，而通用计算机随后也获得了处理原始视频的性能和存储能力。昂贵专用硬件不再是参与数字媒体研究的绝对门槛，工程师可以从现有技术的基本表示方法入手。

本章是一份面向技术读者的入门教程：先说明连续声音怎样变成离散样本，再用采样率、样本格式和通道数描述 PCM，最后讨论数字图像与视频中的像素、帧、隔行扫描、伽马、色彩、色度子采样、像素格式和容器。入门的目的在于建立整体图景；真正编写媒体软件时，这些细节仍然非常重要。

## 从声音到离散信号

声音是压力波在空气中的传播，从声源向周围扩散，类似石子投入水面后泛起的涟漪。人耳和麦克风都能够响应这种压力变化，麦克风把它转换为电信号。

这个音频信号可以看成一维函数：一个数值随时间变化。对于理想化的模拟信号，它在两个意义上都是连续的：

- **时间连续**：每个时间点都有定义，信号平滑变化，不存在因为观察尺度放大而突然出现的空洞。
- **数值连续**：任意时刻的幅度都可以取连续范围内的实数值，而不是只能落在预先规定的若干级上。

经典连续数学适合处理这样的信号。数字信号则在时间和数值上都是离散的。在最常见、最直接的脉冲编码调制（Pulse Code Modulation，PCM）中，系统按固定时间间隔测量瞬时幅度，并把每次测量表示为有限个可能值之一，最终得到一串数字。时间上的离散化是**采样**，幅度只能取有限级则体现了**量化**。

模拟波形与数字序列看起来差异很大，但采样定理说明，两者在满足条件时可以严格地相互转换。克劳德·香农在 1949 年发表了这一定理最具代表性的形式，其基础包括奈奎斯特、哈特利等人的工作。采样定理不仅给出无损转换的条件，也说明条件不满足时，信息会以何种方式、在多大程度上损失或损坏。因此，“数字化”不是无条件保留一切，而是一套有明确边界和误差的表示方法。

## 模拟处理与数字处理的历史选择

数字通信实际上比电话更早。电报比电话早约半个世纪，到 19 世纪 60 年代已经实现机械化自动操作，能够远距离发送编码、复用的数字信号。贝尔实验室的哈里·奈奎斯特研究电报脉冲传输时，提出了后来与奈奎斯特频率相关的工作。需要注意，电报传递的是文本等符号信息，不是把模拟声音采样后得到的数字音频；电话和无线电出现以后，模拟与数字信号技术才继续并行发展。

在很长一段时期里，用模拟电路处理音频要简单得多。课程用几个量级作对比：一个二阶低通滤波器只需要两个无源元件；全模拟短时傅里叶变换可能需要几百个元件，复杂设计甚至达到约一千个。数字信号处理则需要数百万到数十亿个高速晶体管，还需要数字化与模拟重建硬件、控制这些硬件的软件生态，以及保存数据所需的数字存储。缺少通用计算基础设施时，模拟处理自然是更实际的选择。

通用计算机普及后，数字处理的优势变得非常明显：

1. **功能更容易改变**。给专用模拟设备增加功能往往意味着修改硬件；在数字处理器上，可以通过新程序实现新功能。软件并不简单，但通常比重新设计专用模拟系统灵活。
2. **避免逐级累积模拟误差**。现实晶体管、电感和电容都不是理想元件，每个模拟元件都会引入一定噪声和失真。单次影响可能很小，但会逐级累积；模拟信号尤其经过长距离传输后，会受到可测量且不可逆的损害。
3. **便于存储、复制和集成**。单用途模拟部件可能体积庞大，而同样的滤波功能可以在通用硬件上由程序实现。进入数字域以后，存储、复制、处理和传输本身不会像模拟链路那样不断叠加模拟噪声与失真。

数字系统并非绝对理想。应用可能主动使用有损算法，而不可避免的边界仍然存在于数字化和模拟重建阶段，因为数字系统最终要与现实世界中的模拟信号接口。课程指出，现代转换阶段的表现已经足够好，以人的听觉标准衡量，可以视为实际近乎无损。数字音频的优势正是建立在采样理论、转换硬件和通用计算共同成熟的基础上。

## PCM 的三个基本参数

PCM 是原始音频最常见的表示。它并不是唯一的实用表示，例如超级音频 CD 使用 sigma-delta 编码，那是一种脉冲密度调制形式；但 PCM 在数学处理上十分方便，因而占据主导地位。

一个 PCM 表示可以由三个基本参数描述：**采样率、样本格式和通道数**。三者分别回答“多久测一次”“每个幅度数值怎样存储”和“同时有几路音频”。

### 采样率与奈奎斯特频率

PCM 能表示的最高频率称为奈奎斯特频率，它恰好是采样率的一半：

`奈奎斯特频率 = 采样率 / 2`

因此，采样率直接限定了数字化信号中能够出现的最高频率。课程给出了一组常见采样率及其背景：

- 传统模拟电话把语音通道限制在略低于 4 kHz 的带宽内，所以数字电话和许多传统语音应用采用 8 kHz 采样率。8 kHz 音频听起来有些闷，但语音仍然清楚可辨，也是课程所称曾经广泛使用的最低采样率。
- 随着计算能力、内存和存储提升，消费级计算机陆续提供 11、16、22 和 32 kHz 等采样率。采样率与奈奎斯特频率提高后，高频会更清晰，声音也更自然。
- CD 使用 44.1 kHz。它相对 32 kHz 仍有改善，但继续提高采样率带来的听觉收益已经不那么明显。44.1 kHz 在 CD 之前并不常见，是 CD 的成功使它广泛普及。
- 除 CD 外，常见的高保真采样率是 48 kHz。课程认为 44.1 与 48 kHz 几乎没有可听差别；原课程视频本身也采用 48 kHz 音频制作，这对应视频高保真音频的原始标准规格。
- 88、96 和 192 kHz 等更高采样率也逐渐出现。超过 48 kHz 并不只是为了进一步扩展人耳可听的高频，其另一项重要动机与滤波器设计有关。

### 频域、混叠与低通滤波

傅里叶表明，音频信号也可以看成一组组成频率。频域表示与时域表示描述的是同一个信号，只是观察角度不同。借助频域视角，可以更准确地理解采样定理的两个要求。

第一，数字信号不能表示高于奈奎斯特频率的成分。第二，如果采样前没有用低通滤波器去掉这些成分，它们不会简单地消失，而会折叠进可表示的频率范围，形成**混叠失真**。混叠会明显破坏声音，因此必须在采样前限制输入带宽；模拟重建以后，同样需要处理超出奈奎斯特范围的成分。

人的频率感知大致延伸到 20 kHz。使用 44.1 或 48 kHz 采样时，采样前的低通滤波器必须很陡峭：既要尽量保留 20 kHz 以下的可听频率，又不能让奈奎斯特频率以上的成分进入采样过程。现实滤波器无法完美完成这种急剧过渡。

把采样率提高到 96 或 192 kHz 后，低通滤波器的过渡带可以多出一个或两个八度，设计难度随之下降。由此可见，高采样率有时是在为模拟滤波阶段争取更宽裕的过渡区域，而不只是追求人耳听不到的高频。

### 样本格式与量化噪声

采样率决定时间轴上的测量密度，样本格式决定每个幅度数值怎样量化、编码和存储。

#### 8 位线性与非线性编码

早期 PCM 使用 8 位线性编码，把样本存为无符号字节。其动态范围约限制在 50 dB，量化噪声相当明显。课程录制时，普通 8 位音频已经很少见。

数字电话通常采用两种相关的非线性 8 位编码：**A 律（A-law）**和 **μ 律（μ-law）**。它们在较高幅度区域使用更疏的取值间隔，把约 14 位的动态范围压缩进 8 位表示。与线性 8 位编码相比，A 律和 μ 律能够改善量化噪声，而语音的谐波又特别擅长掩盖剩余噪声。

线性 8 位、A 律和 μ 律这三种格式通常与 8 kHz 采样率配合。课程为了演示听感，也将它们放在 48 kHz 下比较；演示条件不改变其典型使用场景。

#### 16 位与 24 位整数 PCM

现代 PCM 常用 16 位或 24 位二进制补码有符号整数，以相应精度编码从负无穷到 0 dB 满量程的范围。最大绝对幅度对应 0 dB；超过这个可表示上限的信号会被削波（clipping）。这里的位数描述每个样本的数值精度，采样率则描述每秒的样本数，两者不能互相替代。

#### 浮点 PCM

混音和母带制作中经常使用浮点 PCM。课程以常见的 32 位 IEEE 754 浮点数为例：它提供约 24 位的分辨率，同时通过浮点指数扩大可表示范围。浮点表示通常把 0 dB 满量程对应为 `±1.0`，但数值本身还可以超过这个范围，因此混音过程中暂时超过 0 dB 不会立即触发削波。

浮点 PCM 占用空间更多，所以通常作为中间制作格式，而不是最终分发格式。它解决的是制作过程中的余量问题，并没有取消最终输出到整数格式时的范围限制。

#### 字节序

通用计算机通常按 8 位字节读写数据。样本超过 8 位时，必须知道多字节数值采用大端序还是小端序，两种顺序都很常见。课程给出的例子是：微软 WAVE 文件使用小端序，而苹果 AIFC 文件倾向使用大端序。忽略字节序会把原本有意义的样本解释成错误数值。

### 通道数与交错

第三个参数是通道数量。原始 PCM 通常把多个通道的样本按顺序交错到同一条流中。例如，多通道音频不是把一整段左声道写完再写一整段右声道，而是依照约定顺序交替排列各通道在同一采样时刻的样本。这种方式直接且易于扩展。

至此，一个原始 PCM 数据块所需的核心描述就完整了：采样率、样本格式和通道数共同决定怎样解释那串数字。

## 从数字音频进入图像与视频

从数学上看，可以把视频理解为在音频的时间维度之外，再增加两个空间维度 `x` 和 `y`。音频只在时间维度采样，而视频在这三个维度上都适用采样定理。不过，实际工程中的视频远比音频庞大和复杂。

课程给出的数据量对比是：原始 CD 音频约为 1.4 Mbit/s，原始 1080i 高清视频则超过 700 Mbit/s。后者每秒需要捕获、处理和存储的数据量超过前者 500 倍。按课程采用的摩尔定律估算，这约相当于八次翻倍，也解释了通用计算机在胜任原始音频之后，为何又过了约 15 年才更容易处理原始视频。巨大的数据量也促使视频采用比线性 PCM 更高效的表示。

视频的复杂性还来自历史。电子视频几乎完全源于广播电视，而广播标准极为重视向后兼容。课程以美国模拟电视广播为例：一台有 60 年历史的黑白电视，在模拟广播退出前仍能显示正常节目。兼容性是一项成就，但代价是某个细节一旦进入标准，就很难再彻底抛弃。

音频技术曾多次从头开始，电子视频却持续累积了数十年针对当时技术限制的巧妙办法。数字视频标准同样继承了大量广播视频概念。因此，下面介绍的不是一套任意设计的计算机图像模型，而是理解现实视频数据所必需的基础。

## 像素尺寸、宽高比与帧率

### 像素数量不等于最终画面比例

原始视频最直观的参数是以像素计的画面宽度和高度。但仅凭像素阵列的宽、高，不能确定显示画面的几何宽高比，因为大量源自广播的视频使用非方形像素。

广播图像的扫描线数量固定，而有效水平像素数取决于频道带宽。水平方向的有效分辨率可能使像素比扫描线间距更窄或更宽。数字采样标准通常要求保留原模拟源的真实分辨率，因此非方形像素也进入数字视频。

课程以一个普通 4:3 NTSC DVD 为例：它通常编码为 `704 × 480`。如果直接把每个像素当作方形，这个像素阵列的比例会宽于 4:3。为此，像素本身被赋予 `10:11` 的宽高比，使像素高度大于宽度，从而在水平方向收窄显示画面，恢复正确比例。要在使用方形像素的数字显示器上正确显示，这类图像需要重新采样。

这个例子说明，软件至少要把“存储了多少像素”和“这些像素以什么形状显示”分开处理。

### 帧率与可变帧率

帧率是每秒显示的完整帧数。数字视频可以采用多种标准帧率，也可以采用其他帧率，甚至让帧率随视频内容自适应变化。一般而言，帧率越高，运动越流畅。不过，在讨论现代逐行帧之前，还需要理解广播历史留下的隔行扫描。

## 隔行扫描与场

早期广播工程师希望用尽可能高的画面更新速度让运动更平滑，并减少磷光 CRT 的闪烁，同时又要在有限带宽内获得较高分辨率。他们的解决办法是**隔行扫描（interlacing）**：

1. 第一次传输偶数行；
2. 下一次传输奇数行；
3. 每一次传输称为一个**场（field）**，两个场大致组成一个完整帧。

两个场能否直接合成一帧，取决于它们是否来自同一个源帧。课程给出的示例中，在每秒 60 个场的画面里，源帧率实际可以是每秒 60 个完整帧；每个场只保留当前源帧的一半，即每隔一行取一行。此时，两个相邻场对应的是不同时间采集的画面，去隔行就不能简单地把它们拼回一帧。

只有在确认奇偶场来自同一源帧时，才可直接合并；否则需要按时间关系进行去隔行处理。“场”与“帧”也不能在软件中当作同义词。

## 伽马与非线性亮度

阴极射线管（CRT）在电子视频的大部分历史中是主要显示技术。CRT 的输出亮度与控制电压不是线性关系：输出亮度约等于输入控制电压的 2.5 次方。指数 2.5 被称为显示器的**伽马（gamma）**。摄像机则近似线性，如果把线性摄像机信号直接送给 CRT，显示的亮度关系就不会保持原来的线性观感。

早期系统预计摄像机数量很少且价格昂贵，电视机数量很多且需要尽量便宜，因此工程师把必要的伽马校正电路放在摄像机端，而不是每台电视机中。广播传输的视频由此带有非线性强度，使用与显示器伽马相反的校正；信号最终到达 CRT 后，从摄像机到显示器的整体响应近似恢复线性。

实际电视系统还有两项调整：

- 电视摄像机采用的指数对应 2.2 的倒数，而不是严格使用 CRT 2.5 的倒数，这考虑了昏暗环境中的观看效果。
- 指数曲线在接近黑色的区域过渡为线性斜坡，这是抑制摄像机传感器噪声的历史办法。

伽马校正还带来了感知上的收益。人眼的感知伽马约为 3，与 CRT 的 2.5 相对接近。经过伽马校正后，表示系统把更多分辨率分给低亮度区域，而人眼恰好在暗部具有更细的亮度辨别能力，因此可用数值范围得到更有效的利用。

CRT 逐渐消失并不意味着非线性亮度消失。标准 sRGB 电脑显示器仍使用类似的非线性曲线：近黑处采用线性斜坡，随后进入伽马约 2.4 的指数曲线。课程以此说明，非线性编码能够把 16 位线性范围映射到 8 位表示，同时把更多可用级差用于暗部。

## RGB、亮度与色度

### 加色与减色

人眼可理解为具有红、绿、蓝三个主要颜色通道。多数显示器使用这三种**加色原色**，组合产生丰富的颜色输出。印刷中的主要颜料则是青、品红和黄，它们属于**减色**系统：青色从反射光中去掉红色，品红色去掉绿色，黄色去掉蓝色。

视频可以直接用 RGB 三个通道表示，有时也确实如此，但典型的视频存储和传输往往采用另一种方式。原因之一是人眼对亮度的敏感度远高于对颜色的敏感度；另一个原因是 RGB 会把图像能量分散到三个通道中，红、绿、蓝平面分别都像原画面的对应颜色版本，承载了重复的画面结构。把这种表示粗略看成“三张黑白图”，并不高效。电视最初从黑白画面起步，也推动了亮度与颜色分离的设计。

### YUV 与 YCbCr

常见视频表示使用一个高分辨率的亮度（luma）通道 `Y` 保存黑白明暗信息，再附加通常分辨率较低的色度（chroma）通道保存颜色。课程用以下关系说明其构造思路：

- `Y`：对独立的红、绿、蓝信号加权后相加；
- `U`：蓝色信号减去亮度，即 `B − Y`；
- `V`：红色信号减去亮度，即 `R − Y`。

当 YUV 为数字视频经过缩放、偏移和量化后，更准确的名称通常是 **YCbCr**。不过，“YUV”仍被广泛用作通称，覆盖这一颜色模型的模拟与数字变体。阅读媒体参数时，需要区分宽泛的习惯称呼和具体数字表示。

## 色度子采样

`U` 和 `V` 可以与 `Y` 具有相同分辨率，但并非必须如此。人眼对空间颜色细节的分辨能力远低于对空间亮度细节的分辨能力，因此可以在水平、垂直或两个方向上降低色度分辨率，通常不会显著损害原始画面的主观质量。

常见形式如下：

| 形式 | 色度处理方式 |
| --- | --- |
| 4:4:4 | 不实际进行色度子采样，色度与亮度保持相同分辨率。 |
| 4:2:2 | `U`、`V` 的水平分辨率减半。 |
| 4:2:0 | 色度的水平和垂直分辨率都减半，因此 `U`、`V` 平面各自只有 `Y` 平面的四分之一大小。课程将其列为最常见的形式。 |

### `4:2:0` 并不是完整的布局说明

4:2:2、4:2:0、4:1:1 等术语只描述了部分分辨率关系，没有完整规定色度样本相对于亮度样本的位置。即使都标为 4:2:0，不同格式仍可能采用不同的**色度样本定位（chroma siting）**。

课程列举 Motion JPEG、MPEG-1、MPEG-2、DV、Theora 和 WebM：它们都使用或可以使用 4:2:0，但色度样本的定位并不统一。

- Motion JPEG、MPEG-1、Theora 和 WebM 都把色度样本放在亮度样本之间，水平和垂直方向均如此。
- MPEG-2 在垂直方向把色度样本放在扫描行之间，但在水平方向与每隔一个亮度样本对齐。
- 隔行模式会进一步改变布局，使定位更复杂。
- PAL DV 总是隔行的。它在水平方向把色度样本放在与每隔一个亮度样本相同的位置，并在垂直方向逐行交替色度通道。

因此，两个文件都写着“4:2:0”，并不意味着解码和显示软件可以省略具体格式的定位规则。

## 打包格式、平面格式与 FourCC

多通道 PCM 音频通常把各通道样本交错排列。视频则同时存在两大类像素组织方式：

- **打包格式（packed）**：交错排列不同颜色通道的数据；
- **平面格式（planar）**：把每个通道的像素分别放在独立平面中，各平面再按顺序堆叠到一帧里。

课程估计，这两个大类合计至少有 50 种格式，其中常见的大约有 10～15 种。不同色度子采样和位深需要不同打包方式，因而形成不同像素格式。即使子采样方式相同，也可能存在多种等价格式，只是通道顺序或数据打包不同；其中一些源于特定硬件上的历史便利。

像素格式通常由独特名称或 **FourCC** 代码标识。处理原始视频时，不能只看 FourCC 就假定已经知道全部语义：它描述像素排列及相应子采样组织，但通常不能据此确定色度样本的具体定位，也不能确定使用哪一种色彩空间定义。

课程以 `YV12` 为例：它可以采用 JPEG、MPEG-2 或 DV 的色度样本定位方式，也可以配合多种 YUV 色彩空间定义中的任意一种。概念上“一帧就是一帧”足以完成许多高层次工作，但真正编写软件时，像素格式、样本位置、位深和色彩定义都会影响数据解释。

## 容器：组织媒体数据与元数据

有了音频样本和视频帧，还需要把它们组织成可存储、可流传输的媒体。

原始音频和视频数据块通常没有外部可见的结构，但大小往往一致。一些简单系统可以按照预先约定的固定顺序把数据块串接起来。然而，压缩帧的大小不一定可预测，应用也经常需要同时使用多种数据类型和多路流。如果只是把没有边界信息的数据依次连接，就会丢失帧之间的分隔，也无法可靠判断某段数据属于哪一路流。

除了信号数据，媒体还必须携带 PCM 参数、视频参数等解释信息，还可能包含：

- 音频标签；
- 视频章节；
- 字幕；
- 解析、导航、处理和展示媒体所需的其他元数据。

**容器（container）**的职责就是保存和组织这些数据。容器为数据块提供帧边界与结构框架，可以交错并标识多条流，提供时间信息，同时保存解析、导航、操作和呈现媒体所需的元数据。从概念上说，容器与所装数据类型相互解耦：容器可以容纳多种数据，数据也可以放入不同容器。

因此，媒体文件不只是压缩后的音频或视频字节序列。样本怎样编码、流怎样同步、帧边界在哪里、属于哪一路流，以及标题和字幕等辅助信息怎样保存，都是完整媒体系统需要回答的问题。

## 小结

数字媒体的核心不是神秘化压缩算法，而是准确理解数据表示。PCM 用采样率、样本格式和通道数描述原始音频；采样率决定奈奎斯特频率，采样前不限制带宽会造成混叠，量化方式和样本格式则决定动态范围、噪声与数值解释。视频在时间维度之外增加两个空间维度，还继承了广播历史中的非方形像素、隔行扫描和伽马校正。为利用人眼对亮度更敏感的特点，视频常把画面分为亮度与色度，并进行色度子采样，但 4:2:0 等标记并不能替代具体的样本定位和像素格式说明。最后，容器把音频、视频、多路流、时间信息和元数据组织为可解析、可导航的完整媒体。
